** ONE ENV VAR REQUIRED IN VERCEL (platform project) **
  SUPABASE_SERVICE_ROLE_KEY = <your Supabase service-role key>
  (Supabase dashboard → Project settings → API → service_role key.)
  Set it as a PLAIN/secret server env var — NOT NEXT_PUBLIC. Without it the
  "Request to book" button returns a configuration error. It is used only in
  app/actions/submitBooking.ts, server-side, for the trusted booking write.

** DATABASE ALREADY LIVE **: a pre-existing bug in the sync_order_status()
trigger (an ambiguous "total") was blocking ALL booking inserts. Fixed straight
in Supabase; you run no SQL.

THE FLOW, END TO END (request-to-book, held; no money):
  1. /experiences/[slug] — real booking control (date, time of day, guests) adds
     the experience to the holistic cart under its venue.
  2. /booking — the cart (rooms + experiences + services), venue-grouped.
  3. /checkout — contact + terms, then "Request to book".
  4. submitBooking (server) RECOMPUTES every price from the database — services
     and experiences from base_price; rooms captured UNPRICED (0 rate plans yet,
     priced at confirmation) — and writes one `order` + a `booking` per venue +
     a `booking_item` per line, status 'Pending' (held). Commission is read from
     the venue's subscription; the cancellation policy is stamped; guest identity
     comes from the session, never the client. Confirmation shows the reference.
  Verified end to end against venue 1137: 2×service @320 = 640, commission 5% =
  32, room captured unpriced, order held. Test data cleaned up.

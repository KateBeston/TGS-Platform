TGS PLATFORM — Cart-event tracking (Phase 1) + holistic cart/checkout
=====================================================================
CUMULATIVE zip: includes the holistic cart + checkout from last time, plus
the behavioural tracking layer. Drop over the matching files. New files:
app/checkout/page.tsx, app/api/cart-event/route.ts.

** DATABASE IS ALREADY LIVE ** — the cart_events table, indexes and RLS were
applied straight to Supabase (project qvriwjipnradsbilepyd). You do NOT run any
SQL. This zip is only the code that writes to it.

TRACKING (Phase 1 — capture only)
  lib/track.ts               — adds trackCartEvent() alongside the existing
      GTM track()/trackOnce(). Fire-and-forget POST to /api/cart-event, sharing
      the page-view session id (sessionStorage 'tgs_sid') so the funnel joins.
  app/api/cart-event/route.ts (NEW) — validates event_type + item_type, sets
      user_id from the AUTH SESSION server-side (never trusted from the client),
      writes one cart_events row. Mirrors /api/pageview; never breaks a page.
  BookingCart.tsx  — fires 'add' / 'remove' / 'quantity_change' with the venue
      and item, via a new venueId prop.
  RetreatVenue/WellnessVenue.tsx — pass venueId to the sidebar.
  app/booking/page.tsx — fires 'cart_view' on load and 'checkout_start' on
      Checkout now.

WHAT IT CAPTURES: viewed (page_views) → add / remove / quantity_change →
cart_view → checkout_start, keyed by session_id (+ user_id when logged in) and
stamped with venue_id. Joins to page_views (session_id) and enquiries (demand)
for Sanctum Institute and venue reporting.

ANALYTICS ONLY: cart_events is never the financial record of a booking. The
'book' event exists for the funnel but is a marker, not money — the authoritative
order is created server-side (the next build).

NOT YET (by design): reporting surfaces (VMS funnel + Institute) = Phase 2 of
analytics; abandoned-cart recovery emails = held behind account-level consent
wording (Jeremy). The order write path (real orders/bookings/booking_items,
test mode) is the next build.
